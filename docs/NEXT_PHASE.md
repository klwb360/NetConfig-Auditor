# 下一阶段执行方案

当前代码和正式v1.1.0发行已经交付，以下工作继续复用现有模块。不得连接或修改真实设备；旧NetAudit删除由用户自行执行。

## P0：补充最终Windows人工环境验收

在独立Windows x64电脑或干净虚拟机，用普通账户验收发行包。记录OS/账户权限/Python安装状态/文件SHA，双击EXE和BAT，实际浏览器导入合成配置并导出JSON/HTML，再在含中文与空格路径运行50文件批量。检查高风险exit1、严格未知exit2、无风险但需复核提示、停止后端口关闭。保存操作记录和已知问题，更新PROJECT_STATUS、检查点并提交；未执行前不得标为通过。本任务核验桌面环境，不重复开发PyInstaller或现有网页。

## P1：扩大语法与规则独立样本（下一1—2周）

1. 先从用户提供的脱敏导出或官方命令参考构建每厂商至少5份更复杂独立预期；标注厂商/版本/支持字段/未知语法及不应报断言，冻结后再测，不能让解析器生成expected。
2. 优先补充路由扩展、ACL绑定和NAT接口地址/服务名/VRF/route-map变体。先复现并新增失败回归，再增量扩展parser/model/rules；未建模期间保持needs-review。
3. 重测95%字段、90%precision、recall单列和80%核心覆盖门槛，按厂商/模块/规则列出分母和失败对象，不用汇总100%掩盖空类别。
4. 每个独立变体提交一个可审阅改动，保存测试/金标准版本/检查点；不改旧固定发行档案。

## P2：GUI批量与报告检索（再1—2周，可按需求选择）

先把既有config_io/batch复用到网页导入，支持批量状态、文件错误和来源导航，再做真实浏览器验收。接口保持单文件报告兼容，不能在批量失败时显示整体安全。若确需历史检索，再以SQLite新增存储；若需公开API再评估FastAPI；Pydantic/TextFSM/YAML用于解决具体验证或维护问题，不为技术栈清单重写现有dataclass和解析器。

每阶段继续更新408笔记、演示和24问答；增加复杂度、数据模型边界、误报/漏报及证据不完整的复试案例。完成后明确新增/修复、验证范围、已知问题与下一检查点。
