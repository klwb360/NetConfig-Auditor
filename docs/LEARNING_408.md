# 从校园网配置理解 408 计算机网络

这份路线把考试概念与可读配置对应起来。先读配置、写下预期，再运行离线解析；工具给出配置事实和待核对风险，不能代替报文、邻居和转发表的验证。

## 一条熟悉的连接链

家中常见连接是 `运营商线路 → 光猫/ONT → 路由器 WAN → 路由器 LAN 或 Wi-Fi → 终端`。校园网可以理解为把 LAN 部分扩大：`终端 → 接入交换机 → 汇聚/核心 → 出口路由/NAT → 运营商`。光猫、路由器、交换机承担的功能不同，不能因为都接网线就当作同一层次的设备。

| 408 概念 | 配置中观察什么 | 离线可确认 | 仍需验证 |
|---|---|---|---|
| 分层与封装 | 接口 IP、VLAN、ACL、静态路由 | 不同功能的配置作用域 | 实际报文经过哪些设备 |
| 以太网交换 | Access、Trunk、VLAN/PVID | 端口显式接入/标签配置 | MAC 表、链路状态、对端标签行为 |
| 广播域 | VLAN 10/20 | 显式 VLAN 及引用 | 动态 VLAN、实际广播传播 |
| IPv4/子网 | 地址和掩码、VRF | 地址/前缀及同作用域重复 | ARP、地址冲突和真实可达性 |
| 路由选择 | 静态前缀、下一跳、OSPF Network | 配置意图及已支持匹配 | 实际 RIB/FIB、最长前缀匹配结果 |
| 可靠/无连接传输 | ACL protocol tcp/udp | 策略匹配的传输层协议/端口 | TCP 状态、重传、应用响应 |
| 应用与管理协议 | SSH、Telnet、HTTP、SNMP | 显式服务/VTY 参数 | 服务是否运行、来源是否可达 |
| 地址转换 | NAT 选流、地址池、服务器映射 | 显式转换规则和引用关系 | 转换表、回程路由、公网暴露 |
| 二层冗余 | STP、edge、BPDU filter | 显式启停和端口属性 | 根桥、阻塞端口、实际环路 |
| 链路状态路由 | OSPF 进程、区域、Router ID | 已支持的进程与选择范围 | Hello/邻居、LSDB、SPF 和收敛 |

## 第 1 次练习：地址、掩码与路由

读取 `huawei-15-self-nexthop-risk.cfg`。接口地址为 `10.15.0.1/24`，网段为 `10.15.0.0/24`；静态默认路由的下一跳也写为 `10.15.0.1`，即本机地址。先预测 `ROUTE-SELF-NEXTHOP`，再运行审计，定位原始行。

把它与 `huawei-16-self-nexthop-control.cfg` 比较：下一跳改为同一连接网段中的其他地址。正确的下一跳配置只是必要条件之一；不能凭这个文件证明邻居存在、ARP 成功或出口能上网。

408 计算练习：目的地址 `192.0.2.80` 同时匹配 `/0` 与 `192.0.2.0/24`，通常按最长前缀优先选择 `/24`。静态配置里写有多个下一跳也可能是 ECMP 或浮动备份，不应直接当冲突。

## 第 2 次练习：VLAN、Access 与 Trunk

读取 `huawei-07-vlan-undefined-risk.cfg`，确认 Access 端口引用 VLAN 30，而输入没有创建 VLAN 30。对比 `huawei-08-vlan-undefined-control.cfg` 的 VLAN 30 定义及描述。结论应是“输入未见定义”，还需确认完整导出、设备 VLAN 数据库与动态创建。

Trunk 用来承载多个 VLAN。`huawei-09-native-vlan-risk.cfg` 显式使用 PVID 1；`huawei-11-pvid-list-risk.cfg` 的 PVID 20 不在显式允许列表。学习时同时列出允许 VLAN、PVID 和对端设置。华为/H3C 的增量允许命令与 Cisco 的替换/追加命令不能机械互换；默认 VLAN、未标记报文和撤销语义依设备支持而定。

VLAN 是二层划分；不同 VLAN 间通常需要三层转发。把两个终端分到不同 VLAN，不会自动建立它们之间的路由，也不会自动完成所有安全隔离。

## 第 3 次练习：ACL 顺序和三层/四层条件

`cisco-17-acl-shadow-risk.cfg` 的前序规则已经拒绝同一 TCP/23 范围，后序许可无法在已解析的顺序语义下命中。用纸写出“协议、源、目的、端口”的匹配条件，再解释为什么是覆盖。

`cisco-18-acl-shadow-control.cfg` 含 `established` 条件，解析器未完整建模 TCP 标志含义。此时应保留原文、标记未知，停止从不完整规则推断全范围覆盖。未知不是 deny，也不是 permit，不能为了给答案而猜测。

ACL 绑定位置和用途同样重要：接口过滤、VTY 管理来源、NAT 选流是不同语义。NAT 使用 `permit` 选择要转换的源地址，不等于放通外侧到内侧的流量。不同厂商/应用的默认动作需核对，不能统一套用一个平台的隐含拒绝规则。

## 第 4 次练习：NAT 与端口

读取 `h3c-07-nat-inbound-risk.cfg`：外侧 `203.0.113.10:443` 映射到内侧主机的 443 端口。区分三个问题：映射是否配置、外侧有没有路径、ACL/防火墙有没有允许访问。文件只能支持第一个问题及局部策略信息。

对比 `h3c-08-nat-inbound-control.cfg` 的撤销命令，理解最终配置由有效命令顺序决定。对比 `h3c-03-nat-acl-risk.cfg`、`h3c-05-nat-pool-risk.cfg`，区分选流 ACL 未定义和地址池未定义。

408 对应：NAT 修改网络层地址，NAPT/PAT 还使用传输层端口区分会话；它不替代加密、认证或完整访问控制。公网能否访问家庭内网还依公网地址、运营商 NAT、映射、回程路由和过滤等条件。

## 第 5 次练习：STP、OSPF 与未知状态

读取 `h3c-09-stp-disabled-risk.cfg` 与控制例，区别“显式 STP 关闭”和“未给出状态”。环路是否存在要看二层拓扑，PortFast/edge 与 BPDU 过滤也要看接口连接对象。STP 属于二层环路控制，不负责选择三层 IP 路由。

`h3c-15-ospf-broad-risk.cfg` 的 Network 范围为 `10.0.0.0/8`，它选择哪些本机接口参与 OSPF，不能直接解释成发布整个 `/8`。配置被动接口不代表协议停用；它主要限制接口发送邻接报文，具体平台行为仍需核对。

缺少认证模式只能得出未确认；看到认证模式也不能证明密钥正确、两端一致或邻接建立。Router ID 是 OSPF 的标识，不等于每个报文的源接口地址。真正运行验证应查看邻居、LSDB、路由表及代表性流量；本项目不连接设备执行这些核查。

## 学习成果自检

1. 不运行工具，写出一个例子的主机名、接口/网段、VLAN、绑定 ACL 和风险对象。
2. 用报告原始行解释为什么触发；再解释控制例为什么不触发。
3. 找一个未知项，说明缺的是语法支持、完整输入还是实时状态。
4. 对比 JSON 清单与手写预期；记录错误值、漏字段和多字段，不用“识别了多少行”代替准确率。
5. 根据一个整改模板写出所需人工参数和回退条件，只在配置副本中练习。

先掌握 IP、掩码、广播域和最长前缀，再学习 STP/OSPF/NAT 的协同。完整 408 还包含物理层、差错控制、拥塞控制、DNS/HTTP 等，本工具的配置练习只覆盖其中一部分。
