# 项目讲解与答辩问答

下面的问题围绕离线校园网络配置学习与审计。回答区分配置事实、静态推断和仍需设备验证的状态，可用作演示或面试准备。

## 1. 项目解决什么问题？

把厂商命令文本转成统一清单，检查显式误配和待核对风险，输出带原始行证据的报告；同时保留配置副本中的离线命令练习。适用于配置阅读、备份审查和学习，不承担设备连接、在线扫描或自动整改。

## 2. 为什么要做统一模型，而不是直接查关键字？

同一句命令可能属于接口、ACL、VTY 或全局；规则需要知道对象、方向、VRF 和最终状态。统一模型把“在哪个对象上配置什么”与厂商语法分开，让相同检查复用同一语义，并保留证据位置。

## 3. 多厂商解析怎样避免混淆？

入口可以显式指定厂商；自动识别只依据可见线索，不能保证每个短片段都有足够信息。解析过程中维护上下文，针对已支持命令处理正向和撤销语义；型号、默认行为及语法差异未得到证据时保持未知。

## 4. 未知为什么要成为一类结果？

缺少命令可能来自配置未导出、默认值不同或解析未支持。把未知当安全会隐藏漏检，把它当确定风险会制造误报。项目用 `null`、warnings 与明确的复核结论保留边界；遇到不完整条件停止相应安全推断。

## 5. `PARSE-INCOMPLETE` 表示什么？

有输入命令的语法或语义没有被完整建模。它证明解析存在覆盖限制，不证明设备存在漏洞。报告保留原文、行号和原因，金标准还检查指定未知命令原文是否仍在 warning 中，避免仅返回一个笼统标记。

## 6. “接口 VLAN 未定义”为什么还需要人工核对？

工具只知道输入有没有受支持的 VLAN 定义。完整配置导出、VLAN 数据库、动态创建和隐式创建行为可能影响判断。因此应描述为输入未见定义，先核对完整性及设备状态，再决定创建 VLAN 或修正引用。

## 7. VLAN 与子网有什么区别？

VLAN 划分二层广播域，IP 子网属于三层地址与路由规划。工程上常把一个 VLAN 对应一个子网，但不是同一个概念；跨 VLAN 通信通常需要三层接口与路由，访问权限还需要 ACL/防火墙等策略。

## 8. Trunk/PVID 检查为什么不能一概判错误？

Trunk 承载多 VLAN，PVID 与允许列表、标签策略和对端设置共同决定行为。全量透传、服务器 Trunk 或有意过滤未标记业务可能合法。工具标出显式设置及一致性问题，保留厂商平台与业务前提供复核。

## 9. 同一 IP 出现两次一定冲突吗？

先看 VRF/VPN 实例作用域；不同路由实例里可以重复地址。同一作用域中的重复地址值得审查，但 anycast、冗余或地址借用设计也需要进一步确认。工具不会仅凭文本断言已经发生 ARP 冲突。

## 10. 为什么静态路由多个下一跳不直接告警？

多个下一跳可能是 ECMP，也可能因管理距离不同而作为浮动备份。需要目的前缀、距离、接口、下一跳解析与实际路由表才能评估。项目检查下一跳等于本机接口地址这种有明确配置依据的情况，避免把合法冗余笼统当冲突。

## 11. ACL 遮蔽怎样判断？

仅在顺序语义明确且两条规则条件都完整时，比较协议、源/目的范围和端口范围。前序规则范围完全覆盖后序规则，后序才属于静态顺序遮蔽。未知选项、硬件 auto 排序和复杂对象组会关闭该推断，不能只看两条文本都有 `any`。

## 12. NAT ACL 的 permit-any 为什么不等于防火墙全放通？

NAT ACL 用来选择转换流量，接口 ACL 或 VTY ACL 用来限制访问。相同 `permit` 在不同用途下具有不同影响。工具区分引用关系和用途；实际公网可达性还要验证路由、映射、回程与过滤。

## 13. STP 关闭告警能证明有环路吗？

不能。它确认输入显式关闭了受支持的 STP 范围。环路风险取决于真实二层冗余路径、设备连接和其他控制；根桥、阻塞端口和 BPDU 流量需要运行状态验证。项目不连接设备取得这些状态。

## 14. OSPF Network 与 Router ID 怎样解释？

Network 语句的地址/wildcard 主要选择本机接口参与进程及区域，不等于无条件发布整个范围。Router ID 是 OSPF 标识；它需要有效且在相关域中满足唯一性要求，但不等于所有接口地址。不同本机进程共用 ID 仍需结合独立域边界核对。

## 15. 看到 OSPF 认证模式就证明邻居安全了吗？

不能。认证模式存在不证明密钥正确、继承有效、两端一致或邻居已经建立。没有完整认证证据则只能要求复核，不能断言可利用的未认证邻接。离线配置与运行状态承担不同证据职责。

## 16. 为什么保留原始行号，还要脱敏？

行号与脱敏后的文本让用户能追溯规则依据，避免黑箱结论；报告、日志和 AI 解释不应暴露常见凭据。脱敏清单不能反序列化为完整可部署配置；需要练习导出时，完整配置副本另有敏感信息保管要求。

## 17. 规则为何采用注册表和每次新实例？

显式插件清单方便检查哪些规则参与审计，扩展时不用依赖隐藏的动态发现。每次创建新实例可避免上一次发现残留到下一次设备。合并发现也要保留所有受影响对象和证据，不能为了减少条目把独立 ACL/NAT 问题合成一个。

## 18. 字段准确率如何避免只统计识别行数？

金标准冻结支持路径，比较实际语义值和类型。准确率分母是预期与实测支持字段键的并集：错误值、遗漏和多解析都扣分。识别行数仅说明解析覆盖；识别 100 行仍可能把 VLAN、端口方向或下一跳全部读错。

## 19. precision 与 recall 有什么区别？

precision 看报出的风险中有多少正确：`TP/(TP+FP)`；recall 看应报风险中找到了多少：`TP/(TP+FN)`。按 `(file,rule_id,affected_object)` 匹配，不能仅比较规则 ID。若应报 10 个只报对 1 个，precision 可为 100%，recall 只有 10%，所以两者都要公开。

## 20. 金标准为什么可信，又有哪些限制？

配置及 expected 在计分前独立人工指定，不从当前解析器/规则输出生成；保留编写记录并冻结文件校验和。计分器有错误值、漏字段、多字段、FP/FN、对象去重和门槛的回归测试。不过它仍是 50 份有限合成片段、25 个风险正反配对；高指标不代表所有设备版本和复杂生产配置都能达到相同性能。

## 21. 如何解释“验收通过但仍有未知提示”？

字段与风险指标达到固定门槛，只说明指定范围的验收达标。未知项单列展示，未被转换为风险 FP 或安全结论；保守解析可能多要求一次复核。使用者应查看未知原文和模块覆盖，再决定补全输入、增加解析支持或进行设备核查。

## 22. 批量模式怎样处理坏文件？

逐文件建立结果，单个编码、大小、解析或读写错误不应让后续有效文件消失。汇总报告保留每个路径、厂商、严重度、风险与错误；默认离线，不启用 AI 或更新情报。测试必须实际验证隔离行为，而不是只断言遍历循环执行。

## 23. TDD 在这个项目中的实际例子是什么？

先写验收计分测试：一个字段正确、一个错误、一个漏掉、一个误多时准确率应为 1/4；一个对象正确、一个错对象和一个额外规则时要同时产生 TP/FP/FN。观察缺失计分器导致测试失败，再实现计分器并确认通过，而不是先写实现后照它写断言。

## 24. 今后最值得增加什么？

先补充独立标注的复杂配置和更多版本覆盖，再扩展有明确语义与回归证据的命令。可增加跨设备两端一致性、完整 OSPF 清单字段验收和更多未知条件场景；这些属于未来工作，不能在当前成果中宣称已完成。设备连接、自动整改和生产配置下发不在现有授权范围。
